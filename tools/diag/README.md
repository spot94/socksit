# Комплект сбора диагностики

Для случая «приложение не ходит через прокси» на чужой машине. Человек запускает батник,
через пару минут получает один текстовый файл и отправляет его вам.

```
tools/diag/
├── Собрать-диагностику.bat      ← это отдать пользователю (двойной клик)
├── Collect-SocksItDiag.ps1      ← сам сбор
└── README.md
```

Отдавать нужно **оба файла** в одной папке: батник ищет скрипт рядом с собой. Проще всего
скопировать папку целиком или заархивировать её.

## Что собирается

| Раздел | Зачем |
|---|---|
| Система, антивирус, процессы | AV с собственным сетевым фильтром ломает TUN; надо знать, запущено ли приложение вообще |
| Служба, версия, `doctor`, `proxytest` | штатная самопроверка SocksIt целиком |
| `socksit.yaml` и `config.json` движка | что реально применено, а не что человек помнит |
| Адаптеры, маршруты, DNS-серверы | MTU туннеля, метрики маршрутов, куда уходят DNS-запросы |
| Резолв `chatgpt.com` и др. | должен вернуть 198.18.x.x — так имя доезжает до прокси |
| Прокси **мимо** SocksIt | исправен ли прокси для **этой** машины: `curl.exe` не в списке приложений, поэтому идёт напрямую |
| `/connections` до, во время и после | главный раздел, см. ниже |
| Лог за время воспроизведения | причина отказа, если движок её пишет |

## Как читать `/connections`

Здоровое проксируемое соединение несёт **имя**: `host = chatgpt.com`, `destIP` пустой.
Прокси сам резолвит имя на своём выходе — ради этого вся схема с fake-ip и существует.

Если в `destIP` стоит `198.18.x.x`, значит движок просит прокси подключиться к адресу,
который существует только на этой машине. Прокси уходит в никуда, байты не идут,
соединения копятся — ровно та картина, которую видно в «Статистике».

Колонка `rule` показывает, какое правило маршрутизации сработало: сразу видно, попало
приложение в список или ушло `direct`.

## Что скрипт меняет на машине

Два временных изменения, оба возвращаются в блоке `finally` и оба записаны в отчёт:

- уровень лога поднимается до `debug` на время воспроизведения;
- `curl.exe` добавляется в список приложений, чтобы прогнать запрос **через** туннель.

Если скрипт прервать на середине, изменения останутся. Вернуть:

```powershell
socksit config app rm curl.exe
socksit config log-level warn
```

Полностью без изменений конфига — `-NoTunnelTest` (тогда не будет раздела «через туннель»).

## Пароли

Логин и пароль прокси вырезаются из `socksit.yaml`, из `config.json` движка и из строк вида
`socks5://user:pass@host`. Перед отправкой файл всё равно стоит открыть и пролистать: это
внутренние адреса и имена машин, отправлять его наружу компании не нужно.
